# リンクの振り分け

[English](requirements.md)

## このドキュメントについて

この機能は、[Chizu](../../product.ja.md)が受け取ったWebリンクの行き先を、利用者の設定に従って決めます。

### スコープ

HTTPとHTTPSのリンク、ブラウザから`chizu-http`と`chizu-https`のスキームで渡されたリンク、URL全体の文字列・正規表現・ホスト・パス・判別できたリンク元アプリによる条件、ブラウザおよびDia・Chrome・Firefoxの`about:profiles`にあるプロファイル指定、通常のファイルによる設定の作成と編集、結果の事前確認、macOSの既定ブラウザの確認・設定を扱います。

### スコープ外

ブラウザ選択画面、Firefoxの新しい「プロファイル」メニューで作ったプロファイル、ブラウザ内で直接開くリンクの検出や横取り、Choosy専用API、無効なChoosyルールの移行は扱いません。

## ユーザーストーリー

### 条件に一致するリンクを指定先で開く

利用者として、リンクのURLやリンク元に応じて行き先を自動で選びたい。それによって選び直す操作をなくせます。

**受け入れ条件:**

Scenario: URLに指定の文字列を含む場合、指定したDiaプロファイルで開く

- Given: URL全体に含む文字列を条件とするルールと、存在するDiaプロファイルが設定されている。
- When: 一致するHTTPまたはHTTPSのリンクをChizuで開く。
- Then: そのリンクのタブが指定のDiaプロファイルに作られ、選択された状態でDiaが前面に出る。

Scenario: ホストとパスに一致する場合、指定したブラウザで開く

- Given: ホストとパスの条件を持つルールが設定されている。
- When: 両方に一致するリンクをChizuで開く。
- Then: 指定したブラウザでそのリンクが開く。

Scenario: Chromeプロファイルを指定した場合、そのプロファイルで開く

- Given: Chromeの画面に表示されるプロファイル名が設定され、その名前のプロファイルが一つ存在する。
- When: 一致するリンクをChizuで開く。
- Then: 指定したChromeプロファイルでそのリンクが開く。

Scenario: Firefoxプロファイルを指定した場合、そのプロファイルで開く

- Given: Firefoxの`about:profiles`に表示される名前で、存在するプロファイルが設定されている。
- When: 一致するリンクをChizuで開く。
- Then: 別のFirefoxプロファイルが起動中でも、指定したプロファイルでリンクが開く。

Scenario: URLが正規表現に一致する場合、指定したブラウザで開く

- Given: URL全体に一致する正規表現を条件とするルールが設定されている。
- When: その式に一致するHTTPまたはHTTPSのリンクをChizuで開く。
- Then: 指定したブラウザでそのリンクが開く。一部だけの一致ではこのルールを適用しない。

Scenario: リンク元を判別できる場合、そのアプリのルールを適用する

- Given: リンク元アプリを条件とするルールが設定されている。
- When: Chizuがリンク元を判別できるWebリンクを受け取る。
- Then: リンク元に一致するルールの行き先で開く。

Scenario: リンク元を判別できない場合、URLのルールまたは既定先を使う

- Given: リンク元アプリを条件とするルールが設定されている。
- When: Chizuがリンク元を判別できないWebリンクを受け取る。
- Then: リンク元アプリだけに依存するルールを適用せず、次に一致するURLのルールまたは既定先を使う。

Scenario: どのルールにも一致しない場合、既定先で開く

- Given: 既定の行き先が設定されている。
- When: 一致するルールのないWebリンクをChizuで開く。
- Then: 設定した既定のブラウザとプロファイルで開く。

### 設定をファイルで管理する

利用者として、振り分けを通常のファイルで編集・同期したい。それによって変更内容を確認し、別のMacでも同じ条件を使えます。

**受け入れ条件:**

Scenario: 設定の構文とコマンド例を確認する

- Given: Chizuがインストールされている。
- When: 利用者が`chizu --help`を実行する。
- Then: 設定ファイルがなくても、コマンドの書式、JSONCの構造とルールの項目、実行例を表示する。

Scenario: サンプルをダウンロードせずに初期設定を作る

- Given: 通常の場所、または明示した場所に設定ファイルがない。
- When: 利用者が`chizu config init`を実行し、必要に応じて`--config FILE`を指定する。
- Then: 親ディレクトリと、Safariを既定の行き先とする空のルールを含む有効なJSONCファイルを作り、そのパスを表示する。

Scenario: 初期設定作成時に既存の設定を保持する

- Given: 指定した設定場所にファイルまたはシンボリックリンクがある。
- When: 利用者がその場所に対して`chizu config init`を実行する。
- Then: 既に存在することを知らせ、ファイルの内容やシンボリックリンクを変更しない。

Scenario: リンクを開かずに振り分け結果を確認する

- Given: 有効な設定ファイルとHTTPまたはHTTPSのURLがある。
- When: 利用者が`chizu check URL`を実行し、必要に応じてリンク元アプリや別の設定ファイルを指定する。
- Then: ブラウザを開かず、一致したルールまたは既定、行き先アプリ、省略可能なプロファイルを表示する。

Scenario: リンクを開かずに設定ファイルを検査する

- Given: 設定ファイルがある。
- When: 利用者が`chizu config check`を実行し、必要に応じて別の設定ファイルを指定する。
- Then: ブラウザを開かず、JSONCとルールが有効かを知らせる。

Scenario: 廃止したコマンド名を受け付けない

- Given: Chizuがインストールされている。
- When: 利用者が`decide URL`、`default-status`、`make-default`、またはURLなしの`check`を実行する。
- Then: リンクを開かず、設定を検査せず、macOSの既定ブラウザも変更せずにエラーで終了する。

Scenario: コメント付きの設定を変更した場合、次のリンクから新しい内容を使う

- Given: Chizuが読み取れるコメント付きJSONの設定ファイルがある。
- When: 利用者がそのファイルを編集し、次のリンクを開く。
- Then: Chizuはコメントを無視し、編集後のルールに従って行き先を決める。

Scenario: ルールが重なる場合、上に書いたルールを使う

- Given: 同じURLに一致するルールが複数ある。
- When: そのURLをChizuで開く。
- Then: 設定ファイルで先に書いたルールの行き先で開く。

Scenario: 設定が壊れている場合、誤った行き先には開かない

- Given: 設定ファイルが存在しない、読めない、または無効である。
- When: Chizuでリンクを開く。
- Then: リンクを他のブラウザへ送らず、設定の問題を知らせる。

Scenario: 正規表現が無効な場合、誤った行き先には開かない

- Given: 設定ファイルのルールに無効な正規表現がある。
- When: 利用者が設定を検査する、またはChizuでリンクを開く。
- Then: そのルール名と正規表現の問題を知らせ、リンクをブラウザへ送らない。

Scenario: 指定のDiaプロファイルがない場合、別プロファイルには開かない

- Given: ルールが存在しないDiaプロファイルを指定している。
- When: そのルールに一致するリンクを開く。
- Then: 他のプロファイルには開かず、見つからないプロファイル名を知らせる。

Scenario: 指定のChromeプロファイルを特定できない場合、別プロファイルには開かない

- Given: 設定したChromeプロファイル名が見つからないか、同じ名前が複数ある。
- When: そのルールに一致するリンクを開く。
- Then: Chromeへリンクを送らず、特定できないプロファイル名と理由を知らせる。

Scenario: 指定のFirefoxプロファイルを特定できない場合、別プロファイルには開かない

- Given: 指定したFirefoxプロファイル名が見つからないか重複している、保存先が存在しない、またはプロファイル一覧を読めない。
- When: そのルールに一致するリンクを開く。
- Then: Firefoxへリンクを送らず、理由を知らせる。

### ブラウザ内のリンクをChizuへ渡す

利用者として、あるブラウザのユーザースクリプトや拡張機能からリンクをChizuへ渡したい。ブラウザ内でクリックしたリンクも、そのリンク用に設定した行き先で開けるようにするためである。

**受け入れ条件:**

Scenario: 渡されたリンクを設定のルールで振り分ける

- Given: `https://team.example.com/projects/1`に一致するルールがある。
- When: ブラウザが`chizu-https://team.example.com/projects/1`を開く。
- Then: Chizuは`https://team.example.com/projects/1`を、HTTPSのリンクを受け取った場合と同じく、そのルールの行き先で開く。

Scenario: 渡されるリンクの行き先を事前に確認する

- Given: 有効な設定ファイルがある。
- When: 利用者が`chizu check 'chizu-https://team.example.com/projects/1'`を実行する。
- Then: ブラウザを開かず、`https://team.example.com/projects/1`と同じ結果を表示する。

Scenario: Webリンクでないものを渡されても開かない

- Given: Chizuがインストールされている。
- When: `chizu-file:///etc/hosts`や`chizu-chizu-https://example.com/`のようなリンクがChizuに届く。
- Then: HTTPとHTTPSのリンクだけを扱うことを知らせ、ブラウザを開かない。

### ChizuをmacOSの既定ブラウザにする

利用者として、システムのHTTPとHTTPSの行き先を確認・設定したい。それによって他のアプリからのリンクをChizuへ送れます。

**受け入れ条件:**

Scenario: macOSの既定ブラウザを確認・設定する

- Given: Chizuがアプリとしてインストールされている。
- When: 利用者が`chizu default status`、続けて`chizu default set`を実行する。
- Then: 最初のコマンドはHTTPとHTTPSの行き先を変更せずに表示し、次のコマンドは両方をChizuに設定して結果を知らせる。

## KPI

### 設定した行き先への到達

- **現状値:** 新規機能のため未計測。
- **目標値:** 受け入れ条件の正常系がすべて成功する。
- **計測方法:** 設定とテストURLを固定して、実際に開いたブラウザ・プロファイルを確認する。
- **計測期間:** 各リリースの検証時。

## 機能要件

### ルール評価

**概要:** ルールを記述順に調べ、最初に一致した行き先を選ぶ。複数の条件を持つルールはすべて満たすときだけ一致する。

**入力:** Webリンク、判別できたリンク元アプリ、設定されたルールと既定先。

**出力:** 開くブラウザ、必要ならプロファイル、または理由を示したエラー。

#### 適用する条件

##### URLとアプリ

URL全体の文字列包含は大文字と小文字を区別しません。URLの正規表現はURL全体に一致した場合だけ適用し、通常は大文字と小文字を区別します。ホストの一致は大文字と小文字を区別せず、パスの前方一致は区別します。リンク元アプリの条件は、そのアプリを判別できたときだけ一致します。HTTPとHTTPS以外のURLは開きません。`chizu-http`または`chizu-https`のリンクは、先頭の`chizu-`を1回だけ取り除いたHTTPまたはHTTPSのリンクとして扱います。

#### 例外ケースでの振る舞い

##### 行き先が見つからない場合

指定されたブラウザやプロファイルが存在しないときは、別の行き先へ黙って変更せず、エラーを示します。Chromeはその画面の名前、Firefoxは`about:profiles`の名前で指定します。名前がない場合や重複する場合もエラーにします。

## データ要件

### 必要なデータ

- **設定:** 既定の行き先、順序を持つルール、URLとリンク元の条件、行き先のブラウザとプロファイル。
- **リンク:** 開くために受け取るURL。リンク元アプリを判別できた場合はその識別子。

### データ間の関係

各ルールは条件と一つの行き先を持ちます。どのルールにも一致しない場合に一つの既定先を使います。

### 個人情報

設定したURLの条件、プロファイル名、リンク元アプリの組み合わせは利用者や勤務先を推測できる場合があります。個人用設定を公開する本体に含めません。受け取ったURLの履歴は保存しません。

## 依存する外部サービス

なし。リンクの送信先となるブラウザは利用者が用意します。

## セキュリティ上の留意事項

渡されたリンクから`chizu-`を取り除く以外に受け取ったURLを書き換えず、設定した行き先以外へ送らないことが必要です。設定の誤りや必要な権限の不足は利用者に知らせます。
